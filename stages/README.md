# 스테이지 뷰어

기존 사이트 상단의 **스테이지** 탭 → 소개 이미지·이름 카드 → 상세 지도.
정적 HTML/CSS/JavaScript + WebGL이며, 서버 API나 외부 런타임 의존성은 없습니다.

- 원본: 로컬 Splatoon 3 v11.2.0 RomFS. 무기 데이터의 v11.3.0과 버전이 다릅니다.
- 25개 대전 스테이지 × 5개 룰, 연어런 7개 + 빅 런 7개 × 3개 수위 = 167개 조합.
- 트리컬러·튜토리얼과 스테이지 목록에서 제외된 대전 원본은 포함하지 않습니다.
- 카드: StageL 원본을 WebP로 변환. 빅 런은 같은 장소의 StageL 이미지를 사용합니다.
- 이름: 원본 VSStageName/CoopStageName 메시지의 14개 지역별 이름. 기존 언어 선택을 공유합니다.
- 룰: Pnt(영역), Var(에어리어), Vlf(타워), Vgl(피시), Vcl(바지락).
- 수위: Low/Mid/High 배치 및 CoopWaterLevelLocator의 실제 Y 좌표. 수위 아래의 표면을 파란색으로 표시합니다.

## 용량과 로딩

대전 125개와 연어런·빅 런 42개, 전체 167개 조합은 같은 미니맵 단순화 지형을 기본 표시합니다. 경사면과 높이 차, 지름 0.5 잉크레일, 반지름 0.8 구형 시작 장치, 스펀지의 초기 크기를 보존합니다.
`minimaps.json`과 `minimap-geometry/`는 사이트 전용 자산으로, 실행 시 실험용 `outputs/` 폴더가 필요하지 않습니다. 동일한 내용은 파일을 공유하며 선택한 룰·수위의 파일 하나만 요청합니다.

기존 렌더 지형 전체 131.659 MB, 썸네일 전체 1.389 MB(십진 MB).
기존 렌더 지형 기준 선택한 룰/수위의 지형은 최소 0.581 MB, 중앙값 2.495 MB, 최대 5.280 MB입니다.
목록에서는 지형을 요청하지 않습니다. 이미지에는 지연 로딩을 적용했습니다.
같은 지형 파일은 메모리에서 재사용하고, 다른 맵으로 바꾸면 해제합니다. 빠른 전환 중 이전 요청은 취소합니다.

`geometry/*.bin.gz`는 내용 기반 파일명입니다. 모든 룰에 동일한 삼각형은 공통 파일로 이동하고, 중복 정점을 인덱스로 공유합니다. STG1 파일에는 위치(1/1000 단위 int32), 법선(int8), 표면 종류(uint8), 삼각형 인덱스(uint32)를 저장합니다. `DecompressionStream`으로 브라우저에서 압축을 풉니다.
이 파일들은 **압축 파일 자체**를 응답해야 하므로 호스팅에서 `Content-Encoding: gzip`을 수동으로 지정하지 마세요. 일반 정적 파일로 제공하면 됩니다.

## 표시의 한계

- 단순화 지형의 칠 가능 여부는 충돌 플래그와 원본 재질의 근접 전사로 추정합니다. paint mask, 면별 예외, ChangePaintableArea는 미반영입니다.
- 단순화 지형의 철망은 충돌 재질 Fence/RopeNet을 기준으로 적갈색·불투명도 45%로 표시합니다. 원래 텍스처 구멍 무늬는 사용하지 않습니다.
- 움직이는 장치는 bind pose 및 배치 초기 위치입니다. 애니메이션·게임 중 상태 변화는 구현하지 않습니다.
- 바다는 실제 물 표면을 시뮬레이션하지 않고, 지형과 수위의 높이를 비교해 표시합니다.
- 모든 맵은 충돌 메시를 바탕으로 미니맵 제외 요소를 걸러내고 얇은 벽에 두께를 준 지형입니다.
- 추출 자산의 권리는 Nintendo에 있습니다. 이 작업은 라이선스 확인이나 공개 배포를 수행하지 않았습니다.

## 다시 추출하기

`tools/StageExport.cs`를 기존 BfresLibrary 및 Syroot DLL로 빌드합니다(.NET 10).

```sh
dotnet build tools/StageExport.csproj -p:BfresLibDir=/path/to/existing/bfres-libraries
python3 tools/export-stages.py \
  --romfs /path/to/latest-v11.2.0 \
  --cache /path/to/conversion-cache \
  --dotnet /path/to/dotnet \
  --model-exporter /path/to/tools/bin/Debug/net10.0/StageExport.dll \
  --texture-decoder /path/to/existing/bntx-extractor \
  --python-libs /path/to/python-libs
```

추출 환경에는 zstd 실행 파일과 numpy, Pillow, byml, texture2ddecoder가 필요합니다. 이미 사용 중이던 BNTX Extractor 0.6 및 swizzle 모듈을 재사용합니다. 해당 추출기는 현대 BRTI의 flags/dim/tileMode 필드 순서에 맞춘 버전이어야 합니다. 이 스크립트에서 실제 BNTX의 tileMode를 옛 swizzle 모듈의 반대 값으로 전달합니다. 외부 라이브러리·원본 RomFS는 저장소에 포함하지 않습니다.

추출기는 정적 배치 actor의 모델을 해석하고, bone hierarchy/rigid skinning을 적용한 뒤 레이어별 지형을 만듭니다. 모든 변환에 성공하면 manifest를 교체합니다. 게임 데이터 버전이나 모델 변환기를 변경하면 별도 캐시 디렉터리를 사용하세요.

## 중심 이동과 높은 지형

처음 열 때는 맵의 기준 방향에서 시계 방향으로 90° 돌린 직교 투영으로 완전히 수직에서 내려다보며, 회전 조작으로 기울여 볼 수 있습니다. 기본 드래그와 방향키는 화면 평면을 따라 지도를 이동합니다. 이동/회전 버튼으로 드래그와 방향키의 동작을 선택하며, 오른쪽 드래그는 항상 회전합니다. Shift+드래그와 Shift+방향키는 회전 모드에서도 이동합니다. 휠은 포인터 위치를 중심으로 확대·축소하며, 터치에서는 두 손가락의 중심 이동과 벌리기·오므리기를 함께 지원합니다. 직교 버튼은 직교/원근 투영을 전환하며 처음에는 직교 투영을 사용합니다. 전환과 전체 보기는 선택한 투영 방식을 유지합니다. 룰 마커는 기존 크기의 1.5배로 표시하며 원근 투영에서도 지형 위치를 따라갑니다. 카메라 리셋은 직교 투영과 기본 위치·회전·확대 배율을 모두 복원하고, 전체 보기는 회전·확대·중심 이동을 처음 상태로 복원합니다.


조작 및 렌더 상태 검증: `node tools/verify-viewer.mjs`.

단순화 지형은 전체 높이를 그대로 표시하므로 높은 지형 숨김 버튼을 사용하지 않습니다.

## 단순화 자산 다시 묶기

`outputs/all-minimaps/`와 `outputs/salmon-minimaps/`의 검증된 결과가 있을 때 NumPy가 설치된 Python으로 `python3 tools/package-minimaps.py`를 실행합니다. 위치는 0.001, 법선은 1/127 정밀도로 저장하며 모든 삼각형과 표면 분류를 보존합니다. `node tools/verify-minimaps.mjs`는 167개 조합의 원본 실험 결과와 사이트 파일을 정밀도 범위 내에서 비교합니다.

## 룰별 목표 표시

대전 25개 맵의 4개 랭크 룰은 `objectives.json`의 목표를 표시합니다. 영역 배틀과 연어런·빅 런에는 표시하지 않습니다.

- 에어리어: PaintTargetArea_Cube/Cylinder의 배치·회전·크기와 SubAreaInstanceIds 연결 구역. 사각형은 전체 폭·깊이, 원형은 반지름 축으로 해석합니다.
- 피시: Gachihoko 최초 등장점, GachihokoCheckPoint 관문, GachihokoGoal 골.
- 타워: Gachiyagura의 ToRailPoint가 연결한 Vlf GachiyaguraRail. 노드를 순서대로 연결하고 CheckPointHP가 양수인 노드에 관문 순서를 표시합니다. 반대편은 VersusMapInfo.IsPointSymmetry에 따라 복원합니다(용궁 터미널은 Z 반사, 나머지는 원점 기준 X/Z 반전). 트리컬러 전용 경로는 제외합니다.
- 바지락: GachiasariGoal 배치 위치에 골 마커. 마커는 장치 배치점을 가리키며 투입구의 3D 모델이나 투입 판정 범위를 재현하지 않습니다.

표시는 지형과 같은 뷰 행렬을 이용한 SVG 주석입니다. 회전·중심 이동·확대에 따라 이동하며 지형 가림 여부와 무관하게 표시됩니다. 주황·보라는 양쪽을 구분하는 색이며 실제 경기의 잉크색·점유 상태를 뜻하지 않습니다. 경로는 배치 노드를 이은 정적 경로이고 타워 애니메이션이나 FillUpType/PositionOffset의 동적 보정은 재현하지 않습니다.

재추출: `python3 tools/export-objectives.py --romfs /path/to/latest-v11.2.0 --python-libs /path/to/byml`
검증: `node tools/verify-objectives.mjs` (100개 랭크 조합, 대칭 경로, 관문 순서, 복수·원형·추가 구역, 화면 투영과 룰 전환 시 제거).

잉크레일 위치 보정: `LinkToPoint`가 가리키는 경로 첫 점에 구형 장치를 놓고, 원본 경로 노드만 연결합니다. Actor Translate를 경로 앞에 덧붙이지 않습니다. `tools/refresh-ink-rails.py`는 지형을 유지한 채 레일만 다시 추출하며, `outputs/all-minimaps/rail-validation.json`에 64개 조합·142개 레일의 노드 대조 결과를 기록합니다. 재추출 후 `tools/package-minimaps.py`로 사이트 파일을 갱신합니다.
타워 점선은 지도 좌표에서 길이 1.5, 간격 1로 먼저 분할한 뒤 투영합니다. 회전·확대 시 화면 픽셀 기준으로 점선 마디를 재배치하지 않습니다.

단순화 지형의 모서리는 얇은 회색 실선으로 표시합니다. 0.01 좌표 단위의 허용 오차로 정점을 묶고 경계와 25도 이상 꺾이는 면의 공유 모서리를 추출합니다. 평면 내부의 공유 대각선과 잉크레일은 제외합니다. 깊이 검사를 유지하며 철망의 반투명 처리를 따릅니다. 검증: `node tools/verify-edges.mjs`.

## 평면 병합 단순화

`tools/simplify-minimap-surfaces.py`는 기존 충돌 지형 결과에서 삼각형별 벽 두께 처리를 되돌린 다음, 같은 평면·표면 종류의 영역을 합칩니다. 칠 가능 여부 경계에서는 앞뒷면의 색 구분을 유지하되, 벽 두께는 표면 종류를 가로질러 합쳐 내부 측면을 만들지 않습니다. 합친 벽의 바깥 경계에만 두께를 주므로 내부 대각선 측면이 사라집니다. 구멍을 보존하는 삼각 분할을 사용하며, 경계 단순화 허용치는 0.015 좌표 단위입니다. 면적 차이가 평면 그룹의 0.2%를 넘으면 해당 그룹의 경계 단순화를 취소합니다. 원래의 삼각형별 0.03 높이 보정은 제거합니다. 전체 경계 상자 차이는 0.08 좌표 단위 이내인지 검사합니다.

변환 환경에는 NumPy와 Shapely 2.1.2가 필요합니다. 브라우저에는 새 의존성이 없습니다. 결과는 `outputs/simplified-minimaps/data/`와 `report.json`에 저장합니다. `tools/package-minimaps.py`는 이 병합 결과가 있는 조합에 우선 적용하고, 잉크레일·스펀지는 기존 결과를 그대로 사용합니다. 기존 추출 파일은 보존합니다.

## 연어런·빅 런 단순화 재생성

`tools/audit-minimap-stages.py`와 `tools/build-all-minimaps.py`에 `--salmon`을 붙이면 14개 맵·3개 수위를 `outputs/salmon-minimaps/`에 만듭니다. 두 스크립트에는 `--romfs`와 `--python-libs`를 전달합니다. 미캐시 모델은 빌더의 `--dotnet`·`--model-exporter`로 변환합니다.

이후 `tools/validate-all-minimaps.py --salmon`, `tools/simplify-minimap-surfaces.py --source outputs/salmon-minimaps`를 실행하고 `tools/package-minimaps.py`로 기존 대전 자산과 함께 묶습니다. Python 라이브러리 경로는 변환 환경에 맞게 지정합니다. 병합 검증 결과는 `outputs/simplified-minimaps/report-salmon.json`입니다.

연어런·빅 런의 첫 화면은 칠 가능한 지형을 기준으로 맞춥니다. 셰케나 댐·난파선 돈 브라코·사계절 훈제 공방은 세 종류의 `DObj_SalmonBouy*` 부표를 모든 수위에서 제외합니다.

연어런 레일은 `InkRailOnlineCoopKeepOn`의 `IsActiveInLow/Mid/High` 설정으로 수위별 표시를 고르고, 연결된 원본 경로 노드와 구형 시작 장치를 표시합니다. 릴레이 이벤트 전용 활성 상태는 일반 수위에 섞지 않습니다. 연어알 바구니·적 출현 지점·이벤트 장치 표시는 포함하지 않습니다. 난파선 돈 브라코와 사계절 훈제 공방의 이동 발판은 초기 배치의 충돌 지형을 유지합니다.

## 무기 팔레트와 사거리 구

- 위쪽은 기존 11개 무기 카테고리, 아래쪽은 해당 종류의 아이콘이 놓인 가로 스크롤 한 줄이다. 검색·드롭다운·배치 버튼과 지형 색상 범례는 사용하지 않는다.
- 팔레트 아이콘을 지형으로 끌면 사거리 구를 미리 보여주고, 유효한 지형에 놓을 때 새 배치를 만든다. 원본 아이콘은 팔레트에 남으므로 같은 무기를 여러 개 배치할 수 있다. 배치·이동은 드래그로 한다. 지도 마커 클릭은 회전 손잡이 표시를 위한 선택이며 빈 지도 클릭·Escape로 해제한다.
- 지도 위 아이콘을 드래그하면 구도 지형 높이를 따라 이동한다. 허공·벽·수면 아래·천장·레일은 배치할 수 없다. 팔레트의 무효 드롭은 새 배치를 만들지 않는다. 기존 마커는 맵의 화면상 경계 또는 지도 화면에서 32px 이상 벗어난 곳, 혹은 브라우저 화면 밖에 놓으면 삭제한다. 경계 근처의 무효 드롭·Escape·포인터 취소는 시작 위치로 되돌린다.
- 모두 지우기 버튼은 지도 안쪽 왼쪽 아래에, 사거리 출처 링크는 지도 아래에 표시한다. 배치·이동 알림, 개별 선택·삭제, 사거리 기준 설명은 사이트에 표시하지 않는다. 팔레트와 지도 위 아이콘의 호버 툴팁에 이름·색상·공격 방식별 칸 수를 표시한다. 평지 유효 사거리, 충전 무기는 풀차지 기준이며 두 공격 방식은 청록·보라 구를 동시에 표시한다.
- 구 중심은 지형점이다. 바닥에서 1.65단위 높인 판정점에서 구 표면까지의 직선이 벽·바닥·경사면(표면 종류 0·1)에 막히면 해당 부분을 회색으로 표시한다. 철망·잉크레일(2·3)은 통과하며 반지름은 유지한다. 두 사거리를 각각 판정하고 드래그 중에도 갱신한다. 곡사·폭발 등 실제 탄도와 명중 여부를 재현하지 않으며, 연어런에서도 대전 무기 기준이다.
- 구 표면까지 직선이 열려 있어도 그 지점에서 수직으로 내린 가장 가까운 바닥점이 같은 판정점에서 가려지면 주황색으로 표시한다. 구 표면 자체가 가려진 회색이 우선한다. 바닥이 없거나 바닥까지 직선이 열려 있으면 기존 청록·보라를 유지한다. 이는 곡사가 필요할 수 있는 영역의 기하학적 구분이며 실제 탄도·낙하 거리·착탄 가능성을 보장하지 않는다.
- 차폐 시작 높이는 사람 형태 잉클링의 판정 높이 약 1.65m(시험장 0.33칸)를 참고한 공통 근사값이다([검증 위키 거리 단위](https://wikiwiki.jp/splatoon3mix/システム詳細仕様#qb0cef31)). 무기별 총구 실측값은 아니다. 구 중심·반지름은 그대로 유지하고, 구 표면과 수직 투영 바닥의 차폐 판정에만 이 높이를 사용한다.
- 지도마다 고체 삼각형의 공간 탐색 트리를 한 번 구성한다. 구는 64×32 분할의 꼭짓점 방향을 판정하고 색을 보간하므로 차폐 경계는 근사치다. 표면 접촉점에서 바깥으로 나가는 방향은 자기 차폐에서 제외한다. 정지한 배치의 판정 결과는 재사용하고 위치·지형 변경 시 다시 계산한다.

### 데이터

기존 `data.js`의 무기 key·SpecActor·종류·다국어 이름과 `assets/` 아이콘, 지형·카메라를 읽는다. `weapon-ranges.json`이 출처 있는 사거리 측정값의 단일 정본이며 기존 무기 성능·지형 자산은 수정하지 않는다. 조정용 밸런스 값이 아니므로 전용 에디터는 만들지 않는다.

카테고리·배치 목록(key, 지형 좌표)·드래그와 미리보기는 임시 화면 상태다. 지도·룰·수위 전환과 새로고침 때 배치를 초기화하며 저장·마이그레이션·랜덤은 없다. 미리보기는 확정 배치와 분리한다. 반지름은 시험장 선 간격 × 5 맵 단위로 파생한다.

- [사거리 측정표 v10.1.0](https://wikiwiki.jp/splatoon3mix/ブキ/ブキ性能#weapon_range), 2026-09-19 확인. 무기 목록 v11.3.0과 버전이 다르며 최신 패치 실측을 보장하지 않는다. 셸터·롤러는 대미지 도달, 블래스터·익스플로셔와 일부 스트링거는 폭발, 스크루는 소용돌이 포함 기준이다.
- [거리 단위](https://wikiwiki.jp/splatoon3mix/システム詳細仕様): 시험장 1칸 = 원본 맵 좌표 5단위. 지도 추출의 월드 좌표는 배율 변경 없이 보존한다.

## 서브·스페셜 마커

`utility-markers.js`가 13종의 표시 정의와 출처를 관리한다. 기존 팔레트 끝의 서브·스페셜 탭에서 드래그하며, 지도 아이콘의 가로·세로는 무기 마커의 80%다. 명칭은 기존 `data.js`의 다국어 sub/special 사전을 읽고 아이콘은 기존 Wsb/Wsp 자산을 쓴다. 지도와 드래그 미리보기에서도 아이콘의 원본 색을 유지한다.

기본값은 메인 목록과 같은 [Leanny/splat3 v11.3.0, 7280ff9](https://github.com/Leanny/splat3/tree/7280ff9cde8bb1c5dcef46c700c326471584d2e6/data/parameter/1130/weapon) 원본 파라미터를 2026-09-19에 확인했다. 아래 수치는 맵 단위이며 시험장 1칸은 5단위다. 기본 0 AP의 최대 전개 상태를 정적으로 표시하며, 마커 팝업에서 개별 기어 파워를 변경할 수 있다.

| 마커 | 표시 | 기준 필드 / 수치 |
|---|---|---|
| 점프 비컨·에너지 스탠드·스프링클러 | 아이콘 | 범위 없음 |
| 그레이트 배리어 | 구 | BarrierParam.MaxRadius = 7.5 |
| 포이즌 미스트 | 구 | AreaParam.DistanceForOff = 5.4 (효과 이탈 경계) |
| 트리플 토네이도 | 원통 1발 | BlastParam.DamageRadiusEnd = 7.7, DamageHeightUp = 20 |
| 나이스옥 | 구 | BlastParam.DamageRadiusEnd = 12.6 |
| 먹구름 | 높은 아이콘 + 시작·도착 원통 | CloudParam.DamageRadius = 10, 표시 높이 20, 이동 약 35 |
| 샤크 라이드 | 도착점 폭발 구 + 출발점/직선 레일 | BulletBlastParam.DistanceDamage = 9(220), 14.9(70) |
| 스플래터컬러 스크린 | 수직 사각 평면 + 방향 화살표 | 폭 27, 높이 9의 평면 근사 |
| 트랩 | 청록 감지 구 + 파랑 폭발 구 | MoveParam.SensorRadius.Low = 3, BlastParam.DistanceDamage[1].Distance = 8 |
| 포인트 센서 | 구 | AreaParam.Distance.Low = 6 |
| 홉 소나 | 수평 원 | WaveParam.MaxRadius.Low = 20 |

스크린의 실제 굴곡·윤곽은 재현하지 않는다. [검증 위키의 전개 폭 5.4칸·높이 1.8칸](https://wikiwiki.jp/splatoon3mix/ブキ/スペシャルウェポン/スミナガシート#spec)을 평면으로 옮겼다. 높이는 원본 WallHeightUp + WallHeightDown = 9와 일치한다. 표시는 배치점부터 위쪽으로 세운 사각형으로, 실제 접촉 판정을 보장하지 않는다. 위에서 볼 때는 얇은 바닥선을 표시한다.

먹구름과 스크린을 클릭해 선택했을 때만 ↻ 손잡이가 나타난다. 선택한 손잡이를 드래그하면 위치를 유지하며 방향을 바꾼다. 손잡이에 포커스하고 방향키를 누르면 15도씩 회전한다. 화면 좌표를 배치 높이의 수평면과 교차시켜 계산하므로 지형 굴곡이나 빈 공간에도 방향 조작이 가능하다. Escape·포인터 취소 시 원래 방향으로 복원한다. Escape는 선택도 해제한다. angle은 배치의 임시 상태이며 지도·룰·수위 전환이나 모두 지우기 때 함께 제거된다.

서브·스페셜에는 메인 무기의 총구 기준 회색·주황 차폐 판정을 적용하지 않는다. 서브·스페셜 범위는 밝은 파랑, 트랩의 청록은 감지 범위다. 원·구 중심은 배치점이며 수평 원과 스크린은 가시성을 위해 배치점보다 0.35단위 높여 그린다. 지형 깊이 검사를 적용하므로 높은 지형에 가려질 수 있다. 먹구름의 시간에 따른 이동·소나 파동 애니메이션·토네이도 3발 자동 배치·트랩 내부 대미지 구분은 재현하지 않는다.

검사: `node tools/verify-utility-markers.mjs` — 12개 아이콘, 구/원통 치수, 트랩 이중 반지름, 방향 역투영과 회전·취소·키보드 조작, 회전 후 캐시 갱신, 기존 총구 차폐와의 분리.

브라우저 확인(2026-09-19): 석순 대협곡에서 신규 서브·스페셜 배치, 토네이도 원통·스크린 평면의 기울인 시점, 먹구름·스크린 방향 드래그, 직교/원근 전환, 룰 변경 시 마커·손잡이 초기화를 확인했다. 같은 줌에서 무기 22.81px, 신규 마커 18.25px로 약 80%였다. 브라우저 경고·오류 없음. 실제 모바일 터치는 이번에 재검증하지 않았다.

마커 드래그 삭제(2026-09-19): 삭제 예정일 때 아이콘을 흐리게 표시한다. 놓을 때만 마커·범위·회전 손잡이를 함께 삭제하며, 맵 안으로 돌아오거나 Escape/포인터 취소 시 삭제하지 않는다. 회전·줌에 맞춰 지형 경계 상자를 화면에 투영해 삭제 경계를 갱신한다. 브라우저에서 맵 바깥 드롭, 지도 영역 위쪽 드롭과 마지막 마커 삭제 후 모두 지우기 비활성화를 확인했다. 새로 연 로컬 화면에서 배리어·먹구름 범위는 파랑으로 확인했고, 관련 모듈의 캐시 갱신 버전을 함께 올렸다.

## 마커 확대와 지형 가림

무기·서브·스페셜에 같은 크기/가림 처리를 적용한다. 줌 1 이하는 기존 배율을 유지하고, 1보다 크면 `0.3 × sqrt(zoom)`을 적용한다. 지도 4배 확대 시 아이콘은 2배 커진다. 서브·스페셜의 무기 대비 80% 크기는 유지하며 방향 손잡이 간격도 새 크기를 따른다.

카메라의 근평면부터 마커 배치점 직전까지 광선을 검사한다. 고체 지형에 막히면 아이콘과 선택된 회전 손잡이를 35% 불투명도로 표시한다. 받침 바닥의 자기 가림, 철망·레일은 제외하며 높은 지형 숨기기 상태도 반영한다. 표시 위치·범위·선택·드래그 동작은 유지한다.

`node tools/verify-marker-visibility.mjs`: 직교/원근 카메라, 벽 앞뒤, 받침 바닥, 철망/레일, 숨긴 천장, 완만한 줌 배율 검증. 브라우저에서는 무기·비컨·먹구름의 크기 증가율, 각각 지형에 가릴 때 35% 표시, 카메라 리셋 후 100% 복귀를 확인했다. 브라우저 오류 없음.


## 먹구름 경로와 샤크 레일

먹구름 아이콘은 배치 지면 위 20단위(표시용 높이)에 뜬다. 아래의 원통은 다른 범위와 같은 불투명도를 쓰며 반지름 10, 지면 +0.35부터 아이콘 높이까지다. 방향을 따라 약 35단위(시험장 7칸) 떨어진 곳에 시작점과 같은 반지름·높이의 흐릿한 도착 원통과 점선 경로를 표시한다. 이동 거리는 [검증 위키 기본 성능표](https://wikiwiki.jp/splatoon3mix/ブキ/スペシャルウェポン/アメフラシ)의 근사값이며, 도착 원통의 바닥은 시작 지면 높이의 수평면이며, 원통 높이는 시작점과 같다. 기어 보정 시 지속 시간 비율로 이동 거리를 늘리며, 진행 시간·지형별 강수 판정은 재현하지 않는다. 방향 손잡이는 구름 높이에서 회전하며, 높은 아이콘을 끌 때 화면상 높이 차이를 보정해 지면 배치점이 튀지 않게 한다.

샤크 마커는 도착점이다. 파랑 구는 반지름 14.9(70 대미지), 보라 구는 반지름 9(220 대미지)다. 바깥 파랑 구의 불투명도 배수는 0.16, 안쪽 보라 구는 0.85로 안쪽 범위를 강조한다. 먹구름 본체 원통·바닥은 다른 범위와 같은 배수 1을 쓰고, 도착 원통은 흐릿하게 유지한다. v11.3.0 `WeaponSpSkewer.game__GameParameterTable.json`의 `BulletBlastParam.DistanceDamage`를 사용한다. 배치 시 출발점은 도착점과 같은 높이에서 25단위 떨어진 위치로 초기화한다([평지 최대 이동 약 5칸 참고](https://wikiwiki.jp/splatoon3mix/ブキ/スペシャルウェポン/サメライド)).

샤크를 클릭하면 출발점의 ● 손잡이가 나타난다. 손잡이를 지형 위로 끌면 출발점만 바뀌고 도착점·폭발 구는 유지한다. 마커를 끌면 도착점만 이동한다. 두 점의 높이를 반영한 직선 레일 두 줄과 가로 침목을 표시하며, 레일의 두 줄과 침목은 모든 삼각형을 지형 깊이 검사 없이 마지막에 그려 지형에 가려져도 보이는 안내선이다. 출발·도착점은 높이 차를 포함한 직선거리 25단위(약 5칸) 안에서만 조정할 수 있다. 한계를 넘겨 끌면 반대쪽 점을 유지하고 끌고 있는 점의 거리는 도달 가능한 지형 경계에서 제한하되, 고정된 반대쪽 점을 중심으로 마우스 방향을 계속 따라간다. 한계 좌표는 지형을 다시 확인해 공중으로 이동하지 않으며 벽 충돌·낙하·실제 주행 가능성은 판정하지 않는다. 무효 드롭이나 Escape/포인터 취소는 출발점을 복원한다. 삭제·맵 전환 시 출발점 손잡이와 레일도 함께 제거한다.

새 상태는 샤크 배치의 `start` 좌표이며, 좌표 변화 시 레일 캐시를 갱신한다. 먹구름의 표시 위치·원통·도착 원은 기존 position/angle과 정의에서 파생한다. 삼각형별 투명도를 별도 속성으로 전달하므로 옅은 원통/도착 원이 기존 무기 범위의 투명도를 바꾸지 않는다.

검사: `node tools/verify-special-routes.mjs` — 구름 높이, 방향별 최대 이동 도착 원, 두 폭발 반지름, 고저차 직선 레일, 투명도 전달, 출발점 변경 캐시 갱신, 도착점 보존, 취소 복원과 높은 아이콘 드래그 보정.


## 마커 우클릭 설정

지도에 배치한 메인·서브·스페셜 마커를 우클릭하면 해당 마커의 설정 팝업이 열린다. 키보드는 마커에 포커스 후 Shift+F10 또는 메뉴 키를 사용한다. 색 선택은 마커 배경에만 적용하고 아이콘 원본·테두리·사거리와 효과 범위 색은 유지한다. 기본값 버튼은 배경색만 복원한다. 외부 클릭·Escape·닫기 버튼으로 닫으며, 마커 삭제·맵/룰/수위 변경·모두 지우기 시에도 닫는다.

서브에는 서브 성능 업, 스페셜에는 스페셜 성능 업을 0–57 AP 정수로 설정한다. 슬라이더와 숫자 입력은 같은 값을 공유하며 즉시 적용한다. 배경색과 AP는 각 배치의 `background` / `gearAP` 임시 상태로, 같은 종류의 다른 마커나 정본 정의를 수정하지 않는다. 기존 배치와 함께 초기화하며 저장·마이그레이션은 없다. 팝업 선택은 UI 상태이고, 보정된 범위는 정본과 AP로부터 계산한다.

범위 보정은 위의 Leanny v11.3.0 원본과 [sendou.ink AP 보간식](https://github.com/sendou-ink/sendou.ink/blob/main/app/features/build-analyzer/core/utils.ts)을 사용한다. AP 효과율은 `min(3.3 × AP − 0.027 × AP², 100) / 100`, Low/Mid/High 사이의 보간은 Mid의 위치를 반영한 지수 곡선이다.

| 마커 | 적용되는 표시 | 원본 Low / Mid / High |
|---|---|---|
| 트랩 | 감지 반지름, 폭발 반지름 | `MoveParam.SensorRadius`: 3 / 3.5 / 4, `BlastParam.SubSpecialSpecUpList.DistanceDamageDistanceRate`: 1 / 1.1875 / 1.375 |
| 홉 소나 | 파동 반지름 | `WaveParam.MaxRadius`: 20 / 24 / 27 |
| 샤크 라이드 | 두 폭발 반지름 | `BulletBlastParam.SubSpecialSpecUpList.DistanceDamageDistanceRate`: 1 / 1.1 / 1.2 |
| 먹구름 | 이동 거리 근사 | `CloudParam.RainyFrame`: 480 / 540 / 600; 기존 35단위에 지속 시간 비율 적용 (57 AP에서 43.75) |

그 외 9종도 AP를 개별 설정할 수 있지만, 현재 표시하는 정적 범위는 달라지지 않는다고 안내한다. 투척 거리·지속 시간·내구도·충전 속도·점프 시간 등을 새로 시뮬레이션하지 않는다. 샤크 레일의 사용자가 정한 출발·도착점도 유지한다. 먹구름 이동 거리는 기존 35단위 근사를 확장한 것이며 원본 경로의 정밀 재현은 아니다.

`node tools/verify-marker-settings.mjs`: 0–57 범위, 중간 AP 비선형 보간, 13종 기본 정의 보존, 트랩·소나·샤크 최대 반지름, 먹구름 경로, 정지 마커의 AP 변경 캐시 갱신, 배경 변경 시 범위 색·형상 보존을 검사한다.

브라우저 확인(2026-09-20): 메인·트랩·홉 소나의 우클릭 팝업, 메인 배경색 변경과 기본값 복원, Shift+F10·Escape·외부 클릭, 트랩 57 AP의 0.8/2.2칸 반지름, 홉 소나 57 AP의 5.4칸 반지름, 99 AP 입력 확정 시 57로 제한, 같은 종류의 새 마커가 0 AP를 유지하는 것, 룰 변경 시 팝업·배치 초기화를 확인했다. 브라우저 경고·오류 없음. 모바일 터치는 검증하지 않았다. 마커 관련 신규·기존 자동 검사 9개를 통과했다.

샤크 거리 제한 확인(2026-09-20): 자동 검사에서 평지·고저차·경계의 빈 지형·큰 포인터 이동·놓기·취소 복원·반대쪽 점 보존을 확인했다. 로컬 브라우저에서 출발점과 도착점을 각각 범위 안쪽으로 이동한 뒤 멀리 끌어도 약 5칸 경계에서 멈추고 반대쪽 점은 유지되는 것을 확인했다. 브라우저 경고·오류 없음. 레일 전체의 지형 가림 제외도 삼각형 단위로 검사했다.


## 마커 16개 성능 기준

성능 측정은 두 사거리를 동시에 표시하는 롤러 16개(사거리 구 32개)를 기준으로 합니다. 배치 개수 제한이나 공유 데이터 형식은 변경하지 않습니다.

구의 64×32 분할과 차폐 판정은 유지합니다. 구의 중복 꼭짓점을 공유하고, 위치가 바뀐 마커만 색을 다시 판정합니다. 화면 이동·확대는 기존 GPU 버퍼를 사용하며 회전 시에는 깊이순 인덱스만 갱신합니다. 32비트 인덱스를 지원하지 않는 WebGL에서는 동일한 형상을 재사용 배열로 그립니다.

```sh
node tools/verify-renderer-performance.mjs
node tools/benchmark-markers.mjs
```

첫 명령은 16개 마커의 인덱스/대체 경로 일치, 정렬, 레일 표시, 캐시 무효화를 검사합니다. 두 번째는 실제 지형을 사용해 초기 준비·회전·이동·한 마커 이동의 중앙값과 95백분위 시간을 출력합니다. Node 측정에는 GPU와 DOM 비용이 포함되지 않으므로 브라우저 프레임 측정과 구분합니다.


2026-09-20 확인: M4 Mac / Chrome에서 석순 대협곡 타워 맵에 롤러 16개를 공유 링크로 복원한 뒤 경사 시점 회전을 180프레임 측정했습니다. 프레임 간격 중앙값 16.6ms, 95백분위 17.5ms였으며, 이동은 중앙값 8.3ms, 95백분위 9.1ms였습니다. 실제 포인터 드래그도 확인했습니다. 이 결과는 해당 기기·맵의 측정이며 모바일 기기 성능 보장은 아닙니다.

같은 지형을 쓰는 Node CPU 벤치마크의 최적화 전/후 중앙값은 회전 115.1 → 약 2.1ms, 한 마커 이동 131.6 → 약 7.5ms입니다. 이 수치는 브라우저 FPS와 별개입니다.

추가 확인: 가장 많은 삼각형(21,824개)을 갖는 다시마 트랙 타워에서도 같은 롤러 16개 경사 회전을 측정했습니다. 프레임 간격 중앙값 8.4ms, 95백분위 16.8ms였습니다. 포인터의 지형 선택은 삼각형마다 임시 배열을 만들지 않는 계산으로 바꿨으며, 해당 맵 200개 광선에서 배치 가능/불가능 결과는 동일하고 위치 차이는 0.000001단위 이내였습니다.


## 폭탄과 스플래시 실드 (2026-09-20)

사용자 승인 범위: 삼각봄·빨판봄·토피도는 폭발 구, 로봇봄은 폭발 구와 인식 구, 컬링봄은 출발·도착점을 조절하는 직선 경로와 거리에서 계산하는 차지 시간·폭발 구, 탄산봄은 최대 차지의 방향 조절 가능한 3연속 폭발, 실드는 스크린처럼 회전 가능한 수직 평면이다. 컬링의 벽 반사와 경사는 계산하지 않는다.

정본은 `utility-markers.js`의 표시 정의다. 기존 아이콘·다국어 명칭·AP·드래그·회전을 재사용한다. 컬링의 `start`와 기존 `position`, 탄산·실드의 `angle`만 배치 수명 동안 수정하고 공유 링크에 저장한다. 거리·차지 시간·반경·연속 폭발 중심은 파생값이며 별도 저장하지 않는다. 삭제·지도 전환은 기존 배치 수명 주기를 따른다. 게임 원본 수치를 옮기는 읽기 전용 도구이므로 별도 밸런스 에디터는 만들지 않는다.

| 표시 | 수치 (맵 단위) | 근거 |
|---|---|---|
| 삼각봄 / 빨판봄 / 토피도 폭발 반경 | 7 / 8 / 6 | Leanny v11.3.0 WeaponBombSplash / Suction의 BlastParam, Torpedo의 BlastParamChase·Throw.DistanceDamage 마지막 거리 |
| 로봇봄 폭발 / 인식 반경 | 6.5 / 12.5 | v11.3.0 WeaponBombRobot.BlastParam, 로컬 v11.2.0 BulletBombRobot_Search.ShapeParam.Cylinder.Radius |
| 실드 폭 / 높이 | 4.5 / 4 | 로컬 v11.2.0 BulletShield_Shield.ShapeParam.Box.HalfExtents (2.25, 2, 0.25); 두께를 생략한 평면 |
| 컬링 폭발 반경 | 5 → 8 | v11.3.0 BlastParamMinCharge / MaxCharge.DistanceDamage 마지막 거리 |
| 컬링 차지 / 평지 거리 | 0–60F / 약 34.5–5 | 원본 WeaponParam.MaxChargeFrame=60, 검증 위키의 약 6.9–1.0칸 |

폭발 수치는 [동일 버전 원본](https://github.com/Leanny/splat3/tree/7280ff9cde8bb1c5dcef46c700c326471584d2e6/data/parameter/1130/weapon)을 사용한다. 로봇봄 원본 인식 형태는 높이 ±4.5의 원통이지만 요청대로 수평 반경 12.5의 구로 표시한다. 토피도의 추가 산탄은 표시하지 않는다.

컬링은 [검증 위키](https://wikiwiki.jp/splatoon3mix/ブキ/サブウェポン/カーリングボム)의 평지 양 끝 거리 사이를 선형 보간하는 **추정 모델**이다. 거리에서 차지 비율을 역산하고, 원본의 60F 및 반경 5–8에 적용한다. 원본 실행 코드의 감속 곡선을 재현한 시뮬레이션이나 게임 실측 결과는 아니다. 서브 성능 업은 원본 SpawnSpeedZSpecUp (0.4 / 0.46 / 0.52)의 비율로 추정 거리 한계를 늘린다. 차지 시간은 60fps로 초로 환산한다. 두 점의 수평 거리만 사용하며 조절 범위를 벗어난 드래그는 제한한다. AP 변경으로 한계를 벗어나면 폭발점은 보존하고 출발점을 한계 거리로 맞춘다.

탄산의 첫 구 중심은 배치점이며 이후 구는 같은 높이에서 방향을 따라 [약 1.5단위씩](https://wikiwiki.jp/splatoon3mix/ブキ/サブウェポン/タンサンボム) 전진한다. 기존 메인 무기의 차폐 색상 판정은 추가하지 않는다. 컬링 경로는 샤크처럼 지형 위에 겹쳐 표시한다.

## 추가 서브·스페셜 표시 (2026-09-20)

현재 승인 범위: 라인 마커와 제트 팩 제외. 퀵 밤은 근/원 폭발 구, 울트라 착지는 본체·양쪽 주먹의 구와 회전, 흡입기는 방향 조절 가능한 원뿔대, 디코이는 폭발 구 하나, 크랩은 연사 사거리와 방향별 최대 거리 카농포 착탄 폭발 구를 함께 표시한다.

정본은 utility-markers.js의 읽기 전용 정의다. position·angle·gearAP와 기존 배치/회전/삭제/공유 흐름을 재사용한다. 보정 반경·회전된 중심은 파생값이다. 새 저장 필드나 에디터는 없다. 제트 팩이 들어 있는 이전 공유 링크는 제트 팩만 제외하고 나머지 마커를 복원한다.

크랩 연사 구의 불투명도 배수는 일반 범위와 같은1이며 파랑 카농포 경로·착탄 구와 함께 보인다. 겹치던 포격 도달거리 구는 생략한다. 디코이는 살포 영역·대표 배치·회전 손잡이를 표시하지 않는다.

표시 근사: 울트라 착지 주먹은 원본 이동거리6.54를 좌우 전방45도로 배치하며 벽 보정·슈퍼점프 발동은 제외한다. 크랩은 배치 높이에서 수평 최대 거리 착탄 예시로 탄도·지형 충돌은 재현하지 않는다. 흡입기는 배치점 위1.65에서 시작하는 수평 원뿔대이며 반격탄은 없다.

기어 효과: 울트라 착지 폭발은1/1.05/1.1, 디코이 폭발은1/1.1/1.2의 Low/Mid/High를 기존 AP 보간으로 적용한다. 흡입기는 시작/끝 반경에 원본 AP 곡선을 적용한다. 크랩·퀵 밤의 표시 사거리/폭발 반경은 기어로 바뀌지 않는다.
